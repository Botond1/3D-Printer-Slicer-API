## 2. HTTP contract for the V3 plugin (stands alone)

### 2.0 What does not change

Base URL `https://api.rocket3d.hu`. Every request the live plugin sends today gets the byte-identical answer it gets from 3.8.3, apart from per-request ids, timestamps and these additive points: a slice receipt's `artifact.retention_seconds` reads **3600** (was 86400); error bodies of archive refusals carry two extra top-level keys (§2.5). `POST /bambu/slice`, `GET`/`DELETE /bambu/slice/jobs/{sj_…}`, `GET /profiles[?contract=material-v1]`, `GET /health`, `GET /pricing`: same paths, fields, statuses, codes, headers, `async_contract: 1`, deadline 900 s, result TTL 30 min. `measurement_generation`, both `catalogue_sha256`, every row's `engine_version` / `effective_profile_sha256` / `engine_build_sha256` / `profile_bundle_sha256`: unchanged, so no open quote stales. Preserve mode is unchanged: `orientationMode=preserve` + `rotationX/Y/Z` (degrees, ≤ 6 dp, R = Rz·Ry·Rx extrinsic X→Y→Z), outcome `preserved`.

Authentication: header `x-slicer-api-key`. All existing keys keep working (§2.8). **A request that carries the header (even empty) and fails authentication always gets today's 401 (`SLICE_SERVICE_AUTH_REQUIRED`, same body), on every route, however many failures came before; it never gets a 429 for the failure.** The key is always compared (a valid key from an IP that also sends wrong keys is always admitted). Failures are counted per source IP; once that IP's failure bucket is spent, the 401 additionally carries `Retry-After`. Only a request with no key header at all can get a 429 from the failure bucket. Wrong-key traffic from the shared egress IP no longer spends the shop's slice tokens. The slice bucket (30/min, burst 20) and the job-route bucket (1 200/min, burst 60) are now kept per authenticated principal, with today's 429 body and `Retry-After`.

Keep sending the private-store basename (never the customer's name) as the multipart `filename`: the sliced artifact's file name on the slicer derives from it.

### 2.2 `POST /bambu/export` — production model with pose and scale baked in

Purpose: at ORDER time, re-prepare the priced model exactly as the priced slice did (unit handling, CAD tessellation, repair, orientation, scale, bed placement) without slicing, and return that mesh. The slicer keeps nothing after a sync answer; an async result is kept until you `DELETE` it or 15 min pass (§2.3).

Auth: slice key. Own rate bucket per principal: **6/min, burst 3** (429 `RATE_LIMIT_EXCEEDED`, `Retry-After`); it never spends the slice bucket. It is not a slice: no native slice runs and no slice budget is touched on the slicer side.

Headers: `X-Request-Id` (optional, echoed), `Prefer: respond-async` (optional; use it from cron), `Content-Type: multipart/form-data`.

Multipart fields: **every field of the priced `POST /bambu/slice` request, with the same names, values and formats** (`choosenFile` = the same bytes, `material`, `layerHeight`, `infill`, `supports`, `orientationMode`, `printerProfile`, `sizeUnit`, `rotationX/Y/Z`, `processProfile`, `scalePercent` if it was sent, `expectedMeasurementGeneration`, `expectedProfileSha256`), plus:

| Field | Format | Required | Meaning |
|---|---|---|---|
| `exportFormat` | `stl` \| `3mf` | no, default `stl` | other value → 400 `EXPORT_FORMAT_INVALID` |
| `expectedSourceSha256` | 64 lower-case hex | yes | receipt `source.sha256`; mismatch → 409 `EXPORT_SOURCE_MISMATCH` |
| `expectedMeasurementGeneration` | 64 hex | **yes here** | receipt `measurement_generation`; mismatch → 409 `SLICE_IDENTITY_MISMATCH` |
| `expectedSlicedGeometrySha256` | 64 hex | no (send it) | receipt `source.sliced_geometry_sha256`; present + mismatch → 409 `EXPORT_GEOMETRY_MISMATCH`; absent → fidelity `unverified` |
| `exportLabel` | `^Q-[0-9]{7}$` | no | written into 3MF metadata only; never into a path or a log |

`expectedProfileSha256` is format-checked and not compared (the export runs no slice profile). Missing or malformed `expectedSourceSha256` / `exportLabel` → 400 `EXPORT_REQUEST_INVALID`. Option errors are the slice's own (same codes, 400).

Check order (all before a queue place, all answered synchronously even with `Prefer`): route enabled (else 404 `ROUTE_NOT_FOUND`) → auth (401) → export bucket (429) → multipart and options (400) → `expectedMeasurementGeneration` vs the running generation (409) → streamed sha256 of the upload vs `expectedSourceSha256` (409) → archive preflight (§2.5) → queue (429 `EXPORT_QUEUE_FULL`, `Retry-After: 10`, when 4 exports are already queued or running service-wide).

Inside the job, the pipeline's own refusals keep their slice codes and statuses (`INVALID_SOURCE_GEOMETRY` 400, `UNSLICEABLE_SOURCE_GEOMETRY`, `AMBIGUOUS_MANUFACTURING_SCOPE` 422, `MODEL_OUT_OF_PRINTER_BOUNDS` 422 with `model_dimensions_mm`, `FILE_PROCESSING_TIMEOUT`, …). Then: `sha256(placed STL)` is compared with `expectedSlicedGeometrySha256` → 409 `EXPORT_GEOMETRY_MISMATCH` with `{actual_sliced_geometry_sha256, orientation_outcome}`; writer failure → 500 `EXPORT_WRITE_FAILED`; sync over 90 s → 504 `EXPORT_DEADLINE_EXCEEDED` with `{retry_async: true}`; async over 900 s → the same code in the job result. Every error body is `{success:false, error:<text>, errorCode:<CODE>, …}`; no `code` key. New codes avoid the substrings `bed bound envelope timeout missing unavailable auth transport rate_limit breaker circuit unhealthy orphaned`.

Sync 200: the body is the file.

```
Content-Type: model/stl | model/3mf
Content-Disposition: attachment; filename="r3d-export.stl" | "r3d-export.3mf"
Cache-Control: no-store            X-Content-Type-Options: nosniff
X-R3D-Export-Contract: 1           X-R3D-Export-Fidelity: exact | unverified
X-R3D-Export-Sha256: <hex of the body>
X-R3D-Sliced-Geometry-Sha256: <hex of the placed STL the export re-prepared>
X-R3D-Measurement-Generation: <hex>
X-R3D-Final-Dimensions-Mm: <x>,<y>,<z>      (3 dp, = model_transform.final_dimensions_mm)
X-R3D-Placement-Mm: <x_min>,<y_min>          (3 dp, the slicer's bed placement)
X-R3D-Orientation-Outcome: applied | unchanged | preserved | fallback_unmodified
X-R3D-Rotation-Matrix: <r00>,<r01>,<r02>,<r10>,<r11>,<r12>,<r20>,<r21>,<r22>   (9 dp, row-major, = model_transform.rotation_matrix, the TOTAL rotation)
X-R3D-Oriented-Dimensions-Mm: <x>,<y>,<z>   (3 dp, = model_transform.oriented_dimensions_mm)
X-R3D-Volume-Mm3: <v>                        (= the placed mesh's volume as the receipt's geometry.volume_mm3 computes it)
X-Request-Id: <echo>
```

Formats:
- `stl`: the exact binary STL Bambu sliced (after placement). With fidelity `exact`, `sha256(body)` = the receipt's `source.sliced_geometry_sha256`: verify it offline, trust nothing. Units mm, Z up, min Z = 0, XY = the slicer's plate placement (re-centre in the operator's tool).
- `3mf`: 3MF core, `unit="millimeter"`, one object `type="model"`, one build item with no transform, the same triangles as the `stl` (float32, bitwise; the writer re-reads and compares before answering). Metadata names (namespace `r3d` = `https://rocket3d.hu/3mf/r3d/1`): `r3d:export_contract` 1, `r3d:fidelity`, `r3d:source_sha256`, `r3d:sliced_geometry_sha256`, `r3d:measurement_generation`, `r3d:printer_profile`, `r3d:orientation_mode`, `r3d:rotation_deg` (`x,y,z`, total), `r3d:scale_percent`, `r3d:placement_mm`, `r3d:final_dimensions_mm`, `r3d:quote_ref` (only with `exportLabel`). `X-R3D-Export-Sha256` is the hash of the 3MF; `X-R3D-Sliced-Geometry-Sha256` still names the STL it was made from. Never a `.gcode.3mf`.

Recommended plugin flow:
1. Async (`Prefer: respond-async`) with `expectedSlicedGeometrySha256` set → `exact`, store, `DELETE`.
2. On 409 `EXPORT_GEOMETRY_MISMATCH` for an `auto` quote (the orientation fell back on its 60 s budget in the priced run or in this one), call again with `orientationMode=preserve`, `rotationX/Y/Z` = the stored receipt's `model_transform.rotation_deg` (the total rotation), and no `expectedSlicedGeometrySha256`; accept only if ALL hold against the stored receipt: (a) every entry of `X-R3D-Rotation-Matrix` equals the receipt's `model_transform.rotation_matrix` within 1e-6; (b) `X-R3D-Final-Dimensions-Mm` and `X-R3D-Oriented-Dimensions-Mm` equal `final_dimensions_mm` / `oriented_dimensions_mm` within 0.01 mm per axis; (c) `X-R3D-Volume-Mm3` equals the receipt's `geometry.volume_mm3` within 0.01 % relative. Dimensions alone are not enough: an upside-down or 180°-turned pose has the same bounding box once placement re-grounds it. Store it labelled `unverified`.
3. Any other refusal: store only the original upload and show the operator that the production model is missing.

Known limit: an export needs the running `measurement_generation` (409 `SLICE_IDENTITY_MISMATCH` otherwise). After a later release that changes the generation, a lock priced under the old generation can no longer be exported exactly; flow step 3 applies. 3.9.0 changes no generation, so this does not arise at this cutover. Export at order creation, not at fulfilment, to keep the window short.

### 2.3 Async export jobs

202 (only with `Prefer: respond-async`): headers `Location: /bambu/export/jobs/ex_<32hex>`, `Preference-Applied: respond-async`, `Retry-After: 2`, `Cache-Control: no-store`; body
`{"success":true,"export_contract":1,"job_id":"ex_<32 hex>","status":"queued","status_url":"/bambu/export/jobs/ex_…","poll_after_ms":2000,"deadline_at":"<ISO>","deadline_ms":900000}`.
Ids start with `ex_` and never match the slice job pattern `sj_`. A job belongs to the principal that created it; any other principal gets 404.

`GET /bambu/export/jobs/{id}` (job-route bucket, `Cache-Control: no-store`, never 304):
- queued/running: `{success:true, export_contract:1, job_id, status:"queued"|"running", queue_position (≥1 while queued), elapsed_ms, deadline_at, poll_after_ms}`
- completed: `{success:true, export_contract:1, job_id, status:"completed", elapsed_ms, result_status:<int>, result:<object>}`. With `result_status` 200, `result` = `{success:true, fidelity, format, media_type, size_bytes, sha256, sliced_geometry_sha256, measurement_generation, final_dimensions_mm:{x,y,z}, oriented_dimensions_mm:{x,y,z}, rotation_matrix:[[…],[…],[…]] (9 dp), volume_mm3, placement_mm:{x,y}, orientation_outcome, file_url:"/bambu/export/jobs/ex_…/file", file_expires_at:"<ISO>"}`; otherwise `result` is the error body of §2.2.
- 404 `EXPORT_JOB_NOT_FOUND`: unknown, deleted, expired (15 min after completion), another principal's, or lost in a restart (resubmit).

`GET /bambu/export/jobs/{id}/file`: 200 with the §2.2 sync headers and body; 409 `EXPORT_NOT_READY` while queued/running or when the job failed; 404 as above. No range requests.

`DELETE /bambu/export/jobs/{id}`: 204 (aborts a running job, deletes the file and the record) or 404. Call it as soon as the file is stored.

Scheduling: an export waits for a free slice slot and starts only when no slice job is waiting; at most one export runs. Exports never take a slice queue place: they count toward neither the 24-job queue nor the 20-per-key share. A slice that needs to run alone (the retry after a system kill) pre-empts a running export: the export is aborted and re-queued at the head of the export class with its deadline still running (`queue_position` reappears in the poll). Deadline 900 s from acceptance.

### 2.4 Deletion of the slicer's copy

- `DELETE /bambu/slice/jobs/{sj_…}` (unchanged statuses 204/404): on a running job it aborts as today; **on a completed job it now also deletes that job's sliced artifact** (the `.gcode.3mf` and its sidecar). If an operator download holds the artifact at that moment, the record is still removed (204), the artifact is marked for deletion and is deleted when that download releases it (or, if the release is lost, by the next periodic sweep, which honours the mark ahead of TTL). To leave nothing on the slicer, `DELETE` each job right after storing its result. The live plugin already sends such `DELETE`s, so from the cutover those artifacts are deleted at once instead of living out their TTL. This also removes the operator's debug copy of every job the plugin deletes (about 300 DELETEs in 11 days); a debug case is reproduced by slicing the stored model again.
- Without a `DELETE`, the artifact is deleted at most 1 h + 5 min after the slice (§3). The uploaded file and every intermediate are deleted when the job settles, in every outcome; a job interrupted by a restart is purged at the next start.
- No delete by content hash exists: nothing keyed by `source.sha256` survives a job except the artifact.

### 2.5 3MF / archive limits and refusals

All are checked before a queue place for a direct `.3mf` upload (sync answer even with `Prefer`) and again inside the job (covers a 3MF inside a ZIP). Error body: `{success:false, error, errorCode, archive_rule, archive_limit}` (`archive_limit` a number or `null`). Read `archive_rule`; the live plugin reads only `errorCode`.

| `archive_rule` | Refused when | HTTP + `errorCode` |
|---|---|---|
| `ARCHIVE_UNREADABLE` | the archive cannot be opened, a required part (`[Content_Types].xml`, `_rels/.rels`, `3D/3dmodel.model`) is missing, declared ≠ actual size, or the file changed during inspection | as 3.8.3 (400 `INVALID_SOURCE_ARCHIVE`) |

"As 3.8.3" means the status and code each existing check returns today are kept exactly (pinned by test T-ARC-1). The Python build walk still refuses > 512 model parts, component depth > 16, > 4096 build items with 400 `INVALID_SOURCE_GEOMETRY` (no `archive_rule`), and modifier/negative parts with 422 `AMBIGUOUS_MANUFACTURING_SCOPE`. Classification note: the LIVE plugin maps `INVALID_SOURCE_ARCHIVE` and `SLICE_RESOURCE_LIMIT_EXCEEDED` to the outage sentence (SlicerDown), without a breaker strike (4xx). The plugin's own container check should mirror these numbers (from §2.1). Tighter plugin numbers would refuse files the slicer prices.

### 2.7 Splitting the automatic pose into tilt and plate turn (plugin-side, no slicer change)

The slice answer's `model_transform.automatic_rotation_matrix` A (3×3, 9 dp; also inside `technical_receipt.geometry.model_transform`) is the orientation the slicer chose in `auto`. Compute in the plugin:

1. d = Aᵀ · (0, 0, −1) — the model-frame direction that ends up facing the plate.
2. T = the minimal rotation taking d to (0, 0, −1): axis = d × (0,0,−1) normalised, angle = acos(d · (0,0,−1)); if d = (0,0,−1), T = I; if d = (0,0,+1), T = Rx(180°).
3. P = A · Tᵀ fixes −z, so it is a pure Z turn; plate turn θ = atan2(P[1][0], P[0][0]) in (−180°, 180°].
4. Postcondition: Rz(θ) · T = A within 1e-9. Send `orientationMode=preserve` and `rotationX/Y/Z` = the X→Y→Z extrinsic Euler angles of T (R = Rz·Ry·Rx) to get the tilt without the plate turn.

Test vector: A = Rz(22°)·Rx(90°) → d = (0, −1, 0), T = Rx(90°) = `[[1,0,0],[0,0,-1],[0,1,0]]`, θ = 22°. For `preserve`/`unchanged`, A = I: T = I, θ = 0. Dropping the plate turn can change the bed placement and the fit (P1S L-footprint): it is a new slice.

### 2.8 Keys after the cutover (no plugin change)

After the cutover the service runs `principals` mode. The shop's current key, whether it is the 64-character former shared key or the 48-character WooCommerce key, authenticates as principal `woocommerce` (the former as rotation `previous`). Staging sites using either key keep working. LeadPilot's key is unchanged.
