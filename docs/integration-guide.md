# Integration guide

Consumer-facing contract of the 3D Printer Slicer API as of version 3.3.0
(2026-09-02). It is written for the two integrating systems (the WooCommerce
plugin and LeadPilot) and covers only what a consumer can call. The
operator-facing surfaces (pricing administration, artifact download,
operations diagnostics) are documented in `README.md` and are never exposed
to consumers.

Interactive reference: `GET /docs` (Swagger UI) and `GET /openapi.json` on the
running service. When this guide and the OpenAPI document disagree, the
OpenAPI document generated by the running version wins.

## 1. Authentication

Every slice and render request carries exactly one header:

```text
x-slicer-api-key: <your slice credential>
```

- Each consumer receives its own credential family (WooCommerce and LeadPilot
  are separate principals). Consumers never receive `x-api-key` material; that
  header belongs to the operator-only pricing, artifact, and operations
  audiences and is not accepted as a slice credential.
- A missing, wrong, or retired key returns HTTP `401` with this exact body,
  before any upload is stored or queued:

```json
{
  "success": false,
  "error": "Slice service authentication is required.",
  "errorCode": "SLICE_SERVICE_AUTH_REQUIRED"
}
```

- Rotation is announced in advance: a replacement key is issued while the old
  one keeps working, the consumer switches, then the old key is revoked.
- Requests without an `Origin` header (server-to-server) are always allowed.
  Browser-origin calls are only accepted from an operator-configured exact
  origin allowlist.
- `X-Request-Id` (1–128 characters, alphanumeric plus `. _ : -`, starting
  alphanumeric) is echoed back; invalid values are replaced. Send one to
  correlate your logs with the service's.

## 2. Network prerequisites

The public route admits exactly one allowlisted caller address per consumer.
Three distinct failure layers exist:

| Symptom | Layer | Meaning |
| --- | --- | --- |
| TCP connect timeout, no HTTP response at all | host firewall | the source address is not allowlisted; nothing is wrong with the API |
| HTTP `403` with body `Forbidden` and no `Content-Type` | edge router | the address reached TLS but is not in the router allowlist |
| HTTP `401` with the JSON body above | API | the key is missing, wrong, or retired |

Report host rebuilds or address changes before they happen: the allowance is
address-level, so a reassigned address silently loses (or gains) access.

## 3. Endpoints

All four endpoints accept `multipart/form-data` with the model in the field
`choosenFile` (the legacy spelling is intentional). They share one rate limiter
and one FIFO queue, so a preview never runs beside a native slice.

| Endpoint | Engine | Technology | Result |
| --- | --- | --- | --- |
| `POST /prusa/slice` | PrusaSlicer 2.8.1 | FDM or SLA by `layerHeight` | JSON quote |
| `POST /orca/slice` | OrcaSlicer 2.3.1 | FDM only | JSON quote |
| `POST /bambu/slice` | Bambu Studio 02.08.02.61 | FDM only | JSON quote, `placement_mm` |
| `POST /render` | none (renderer) | n/a | `image/png` 1024×768 preview |

Accepted upload formats: `.stl`, `.obj`, `.3mf` (direct); `.stp`, `.step`,
`.igs`, `.iges`, `.ply` (CAD, converted); `.zip` containing exactly one of the
above (junk entries such as `__MACOSX/`, `.DS_Store`, `Thumbs.db`,
`desktop.ini` are tolerated). A 3MF scene with several objects is merged into
one compound model; the objects keep their relative placement. Maximum upload
size is 500 MB. Geometry is never repaired: a broken mesh is rejected, not
fixed.

### 3.1 Request fields common to the three slice endpoints

| Field | Type / values | Default | Validation |
| --- | --- | --- | --- |
| `choosenFile` | file | required | extension allowlist above |
| `layerHeight` | engine-specific, see below | `0.2` | exact match against the engine's list |
| `material` | FDM: `PLA`, `PETG`, `ABS`, `TPU`; SLA (Prusa only): `Standard`, `ABS-Like`, `Flexible` | `PLA` (FDM), `Standard` (SLA) | must exist for the selected technology; case-insensitive |
| `infill` | integer `0`..`100`, optional trailing `%` | `20` | strict integer, never clamped; anything else is `400 INVALID_INFILL` |
| `supports` | `true` / `false` | `true` | any other present value is `400 INVALID_SUPPORTS`; empty string keeps the default |
| `orientationMode` | `auto` / `preserve` | `auto` | any other present value is `400 INVALID_ORIENTATION_MODE` |
| `sizeUnit` | `mm` / `inch` | `mm` | applies to `targetSizeX/Y/Z` |
| `keepProportions` | `true` / `false` | `true` | with several target axes and `true`, the model is fitted within the box (smallest ratio wins) |
| `targetSizeX`, `targetSizeY`, `targetSizeZ` | positive number | none | cannot be combined with `scalePercent` (`400 CONFLICTING_SIZE_OPTIONS`) |
| `scalePercent` | positive number | none | uniform scale |
| `rotationX`, `rotationY`, `rotationZ` | degrees, finite number | `0` | applied after automatic orientation, in X, Y, Z order |
| `printerProfile` | engine-specific | engine default | see below |
| `processProfile` | Orca and Bambu only | derived from `layerHeight` | see below |

Processing order: format conversion → automatic orientation (unless
`preserve`) → sizing → requested rotation → placement on the plate. Option and
profile validation runs before queue admission, so a `400` never consumes a
queue slot.

### 3.2 `POST /prusa/slice`

- `layerHeight`: `0.025`, `0.05` select SLA; `0.1`, `0.2`, `0.3` select FDM.
- `printerProfile`: INI basename from the server's Prusa profile set. The
  P1S profiles are `FDM_0.1mm.ini`, `FDM_0.2mm.ini`, `FDM_0.3mm.ini` (selected
  automatically by `layerHeight`); the H2D-sized quote profiles are
  `FDM_P1S_H2D_SIZE_QUOTING_0.1mm.ini`, `..._0.2mm.ini`, `..._0.3mm.ini`.
- SLA (`SLA_0.025mm.ini`, `SLA_0.05mm.ini`) produces a print-time estimate
  only; see section 6.

### 3.3 `POST /orca/slice`

- `layerHeight`: `0.1`, `0.2`, `0.3`.
- `printerProfile`: `Bambu_P1S_0.4_nozzle.json` (default) or
  `Bambu_P1S_H2D_SIZE_QUOTING_0.4_nozzle.json` (H2D-sized quote bed, P1S
  physics).
- `processProfile`: `FDM_0.1mm.json`, `FDM_0.2mm.json`, `FDM_0.3mm.json`
  (selected automatically by `layerHeight`). An incompatible pair returns
  `422 ORCA_PROFILE_INCOMPATIBLE`.

### 3.4 `POST /bambu/slice`

Uses the official Bambu Lab vendor profiles bundled with Bambu Studio, so time
and mass reproduce the Bambu Studio GUI readings (section 8).

- `printerProfile`: `P1S` (default) or `H2D`, case-insensitive; `printer` is
  an accepted alias. Anything else is `400 INVALID_PRINTER_PROFILE`.
- `layerHeight` keys per printer:
  - P1S: `0.08`, `0.1`, `0.12`, `0.16`, `0.2`, `0.24`, `0.28`
  - H2D: `0.08`, `0.1`, `0.12`, `0.16`, `0.2`, `0.24`
  - `0.1` selects the vendor 0.12 mm process with the layer height overridden
    to 0.1 mm, exactly as a GUI user would do. Other values return
    `400 INVALID_LAYER_HEIGHT` listing the allowed keys.
- `processProfile` (optional): an exact vendor process name offered for the
  printer, for example `0.20mm Standard @BBL X1C` (P1S) or
  `0.20mm Standard @BBL H2D`. Unknown names are `400 INVALID_PROCESS_PROFILE`.
- `material`: `PLA`, `PETG`, `ABS`, `TPU`, mapped to the vendor "Generic"
  filaments (`Generic PLA`, …, and the `@BBL H2D` variants on the H2D). A
  material without a mapping is `400 MATERIAL_PROFILE_UNAVAILABLE`.
- Bed placement is done by the API (native arrangement is off), and the chosen
  position is reported in `placement_mm`. The P1S bed has an excluded
  `18 × 28 mm` corner at the origin, so its admissible footprint is L-shaped:
  up to `256 × 228 mm` placed above the corner, or up to `238 × 256 mm` placed
  beside it. The H2D single-filament area is the first extruder's
  `325 × 320 mm`.

### 3.5 `POST /render`

Returns a deterministic PNG of the exact pose the slice pipeline would slice.

- Fields: `choosenFile` (required), `orientationMode`, `sizeUnit`,
  `keepProportions`, `targetSizeX/Y/Z`, `scalePercent`, `rotationX/Y/Z`, and
  optionally `layerHeight` / `material` (validated like `/prusa/slice` so the
  orientation heuristic matches; they do not change the image).
- Response: `Content-Type: image/png`, `Cache-Control: no-store`, 1024×768,
  isometric camera, light background with a build-plate grid, caption
  `X x Y x Z mm` bottom-left. Identical input bytes and options give
  byte-identical PNGs, so the image can be cached by content hash.
- Bounds are checked against the largest supported FDM envelope
  (`350 × 320 × 325 mm`), not a printer profile. Rendering has a 60 s budget;
  exceeding it returns `422 FILE_PROCESSING_TIMEOUT`.

## 4. Success response

All three slice endpoints return the same shape. Engine-specific parts are the
`profiles` object and, for Bambu only, `placement_mm`.

Common fields:

| Field | Meaning |
| --- | --- |
| `job_id`, `artifact_id` | correlation identifiers (no paths, no file names) |
| `slicer_engine` | `prusa`, `orca`, or `bambu` |
| `engine_version` | version reported by the native binary that produced the result |
| `technology` | `FDM` or `SLA` |
| `material`, `infill`, `supports` | effective values used for the slice |
| `profiles.effective_profile_sha256` | identity of the effective machine/process/filament chain (section 5) |
| `model_transform` | schema 2 provenance: orientation mode/outcome, requested/automatic/total rotation, and `original_dimensions_mm` → `oriented_dimensions_mm` → `final_dimensions_mm` (all in mm) |
| `build_volume_limits_mm` | `min`, `max` (the inclusive admission ceiling) and `source_profile` |
| `placement_mm` | Bambu only: `x_min`, `y_min` of the placed bounding box on the bed |
| `hourly_rate` | HUF per hour used for pricing, or `null` |
| `stats.print_time_seconds` | integer seconds; Orca and Bambu report the total including the start sequence |
| `stats.print_time_source` | which marker produced the time (`total_estimated_time`, `m73_p0_r_minutes`, `estimated_printing_time`, `time_seconds`, or an SLA estimate label) |
| `stats.material_used_m` | filament length in metres |
| `stats.material_used_g` | filament mass from the slicer's own marker, or `null`; never derived from length; always `null` for SLA |
| `stats.object_height_mm` | equals `model_transform.final_dimensions_mm.z` |
| `stats.estimated_price_huf` | integer HUF, or `null` (section 6) |

`model_transform.orientation_outcome` is one of `applied` (auto rotated the
model), `unchanged` (auto kept the pose), `preserved` (you asked for the
submitted pose), or `fallback_unmodified` (automatic orientation was
unavailable and the converted model continued as submitted).
`original_dimensions_available` is `true` exactly when
`original_dimensions_mm` is a real pre-orientation measurement and `false`
exactly when it is `null`.

The examples below use the same 40 mm PLA cube at 0.2 mm, 20 % infill,
supports on, measured on the current image (2026-09-02). `print_time_readable`
is a human-readable `<h>h <m>m` string and is not meant to be parsed. The
`material_used_m` values in the examples are derived from the measured mass
and the profile density; the service reports the slicer's own length marker.

## 5. Calibration keys: `engine_version` and `effective_profile_sha256`

A quote is only comparable with another quote produced by the same effective
configuration. Two response fields identify that configuration:

- `engine_version` changes when the native slicer binary changes.
- `profiles.effective_profile_sha256` is a deterministic SHA-256 over the
  effective machine, process, and filament profile content, the normalised
  material, and the server-owned invocation policy. It excludes the
  per-request `layerHeight` and `infill` overrides; the default
  `supports=true` leaves it unchanged, while `supports=false` selects a
  different effective profile and therefore a different digest. Any change to
  profile content (a speed, a temperature, a bed size) changes it; a
  layer-height or infill change does not.

Key every calibration or correction table by
`(slicer_engine, engine_version, effective_profile_sha256, material,
layerHeight, infill, supports)`. When either identity value changes, treat the
old calibration as void and re-measure.

Change-notification promise: profile content or engine changes that alter
`engine_version` or `effective_profile_sha256` are announced to consumers
before deployment and recorded in `CHANGELOG.md`. The current identities are
listed by `GET /profiles`, which is the reference to diff against.

## 6. Price semantics

- The price is time-only: mass is reported but not billed.
- `estimated_price_huf = ceil(max(print_time_seconds, 900) × hourly_rate / 3600)`,
  rounded up to the nearest 10 HUF, computed in integer arithmetic (1980 s at
  800 HUF/h is exactly 440, not 450). The minimum billable time is a quarter
  hour.
- `hourly_rate` comes from the operator's pricing file for the technology and
  material; the public `GET /pricing` shows the current matrix.
- `estimated_price_huf: null` (with `hourly_rate: null`) means "quote manually".
  It happens when the native output carries no positive mass marker for an FDM
  slice and when an Orca material has no server-owned filament profile. Never
  treat `null` as zero.
- SLA responses (Elegoo Saturn 4 Ultra quoting profile) are priced: the print
  time is `layer_count`-based (`print_time_source: sla_layer_time_model`,
  bottom layers x (30 s + 6 s) + 8 transition layers + remaining layers x
  (exposure + 2.5 s tilt), owner-tunable in the server registry) and
  `material_used_g = material_used_ml x resin density` (Standard/ABS-Like
  1.10, Flexible 1.05 g/cm3). `stats.layer_count`, `stats.model_volume_ml`
  and `stats.support_volume_ml` are reported; the two volumes are `null` for a
  mesh that is not watertight, because the model's own volume cannot be
  measured there (the price never depends on them). `supports=false` is
  honoured on SLA too and is a different effective profile, exactly as on FDM.
  PrusaSlicer places SLA support points non-deterministically, so two identical
  SLA requests can differ slightly in support volume, mass and price (measured:
  36.03 ml against 36.25 ml on the same overhang model, about 0.6%); an FDM
  quote does not vary this way. The per-layer motion time is a
  documented assumption until the owner calibrates it against the printer's
  own estimate; treat SLA prices as calibrated only after that.

## 7. Error table

Every non-2xx response is JSON `{ "success": false, "error": "...",
"errorCode": "..." }` unless noted. "Retry" means the same request may
succeed later without changes.

| HTTP | `errorCode` | Retry | Meaning |
| ---: | --- | --- | --- |
| 400 | `NO_FILE_UPLOADED` | no | `choosenFile` missing |
| 400 | `UNSUPPORTED_FILE_FORMAT` | no | extension not allowed |
| 400 | `INVALID_SOURCE_ARCHIVE` | no | ZIP invalid, encrypted, unsafe, or without exactly one supported file |
| 400 | `INVALID_SOURCE_GEOMETRY` | no | converter found invalid or non-printable geometry; nothing is repaired |
| 400 | `INVALID_MULTIPART_REQUEST`, `UPLOAD_REQUEST_ABORTED` | no / yes | malformed multipart body / client closed the upload |
| 400 | `INVALID_LAYER_HEIGHT`, `INVALID_LAYER_HEIGHT_FOR_ENGINE`, `INVALID_LAYER_HEIGHT_FOR_TECHNOLOGY` | no | layer height not offered by the engine/technology |
| 400 | `INVALID_MATERIAL_FOR_TECHNOLOGY`, `MATERIAL_TECHNOLOGY_MISMATCH` | no | material not configured for FDM/SLA |
| 400 | `MATERIAL_PROFILE_UNAVAILABLE` | no | Bambu: material has no vendor filament mapping for the printer |
| 400 | `INVALID_INFILL`, `INVALID_SUPPORTS`, `INVALID_ORIENTATION_MODE` | no | strict option validation |
| 400 | `INVALID_SIZE_UNIT`, `INVALID_KEEP_PROPORTIONS`, `INVALID_SIZE_OPTIONS`, `CONFLICTING_SIZE_OPTIONS`, `INVALID_ROTATION_OPTIONS` | no | sizing/rotation option validation |
| 400 | `INVALID_PRINTER_PROFILE`, `INVALID_PROCESS_PROFILE` | no | Bambu registry id / vendor process name unknown |
| 400 | `INVALID_PROFILE_NAME`, `PROFILE_NOT_FOUND` | no | Prusa/Orca profile override unsafe or absent |
| 401 | `SLICE_SERVICE_AUTH_REQUIRED` | no | key missing, wrong, or retired |
| 408 | `UPLOAD_TOTAL_TIMEOUT` | yes | the multipart upload took longer than 600 s; the connection is closed |
| 413 | `UPLOAD_RESOURCE_LIMIT_EXCEEDED`, `SLICE_RESOURCE_LIMIT_EXCEEDED` | no | upload, archive expansion, model, or output exceeded a size limit |
| 422 | `MODEL_OUT_OF_PRINTER_BOUNDS` | no | does not fit; body also carries `model_dimensions_mm`, `build_volume_limits_mm`, and the full `model_transform` |
| 422 | `MODEL_DIMENSIONS_UNAVAILABLE` | no | the model could not be measured after conversion |
| 422 | `UNSLICEABLE_SOURCE_GEOMETRY` | no | the native slicer refused the mesh (empty layer, faulty mesh, load failure); `detail` explains, path-free |
| 422 | `ORCA_PROFILE_INCOMPATIBLE` | no | Orca machine/process pair rejected |
| 422 | `FILE_PROCESSING_TIMEOUT` | maybe | a processing budget expired (native slice 600 s, Python helpers 120 s each, render 60 s); simplify the model before retrying |
| 422 | `INVALID_SLICE_OUTPUT`, `INVALID_SLICE_STATS` | yes | generated artifact or statistics failed validation |
| 429 | `RATE_LIMIT_EXCEEDED` | yes, after `Retry-After` | per-caller token bucket exhausted; `retryAfterSeconds` in body |
| 429 | `SLICE_QUEUE_CLIENT_LIMIT` | yes, after `Retry-After` | more than 5 queued+active jobs for this caller; `Retry-After: 5` |
| 500 | `SLICE_OUTPUT_UNPARSED` | yes | required time/length/mass marker missing or drifted; no estimate is invented |
| 500 | `NATIVE_OUTPUT_OVERFLOW` | maybe | native process exceeded its output buffer and was stopped |
| 500 | `INTERNAL_PROCESSING_ERROR`, `QUEUE_INTERNAL_ERROR`, `UPLOAD_STORAGE_ERROR`, `INTERNAL_SERVER_ERROR` | yes | internal failure, logged server-side |
| 503 | `SLICE_QUEUE_FULL` | yes, with backoff | more than 100 queued jobs |
| 503 | `SLICE_QUEUE_TIMEOUT` | yes, with backoff | the request waited more than 300 s in the queue |
| 503 | `SLICE_QUEUE_SHUTDOWN` | yes, after a pause | the service is restarting |
| — | connection timeout | no | the caller address is not allowlisted (section 2) |
| 403 | plain `Forbidden`, no JSON | no | edge router allowlist (section 2) |

Do not parse the `error` text; branch on `errorCode` only.

## 8. Engines, printers, and calibration status

| Printer | Prusa | Orca | Bambu |
| --- | --- | --- | --- |
| Bambu Lab P1S | `256 × 256 × 249.9` mm (generic Marlin profile) | `253.9 × 253.9 × 249.9` mm (generic Marlin profile) | `256 × 228 × 250` mm, alternative footprint `238 × 256` (official vendor profile) |
| Bambu Lab H2D | `350 × 320 × 324.9` mm as `H2D-QUOTE` (P1S physics on an H2D-sized bed, quote only) | `347.9 × 317.9 × 324.9` mm as `H2D-QUOTE` (same) | `325 × 320 × 325` mm, single-filament first extruder area (official vendor profile) |

| Elegoo Saturn 4 Ultra (SLA) | `218.88 x 122.88 x 220` mm as `SATURN4U` (API-enforced: the PrusaSlicer SLA export itself does not refuse out-of-bed objects) | - | - |

All values are inclusive: a model exactly on the value is accepted.

Measured on 2026-09-02 against the owner's Bambu Studio GUI readings of the
ten reference models: the Bambu Studio 02.08.02.61 headless CLI reproduces the
GUI within −1.1..+0.1 % on time and 0..0.2 % on mass with supports off, so
`POST /bambu/slice` is the quoting authority for Bambu Lab printers.
OrcaSlicer 2.3.1 with its bundled BBL profiles deviates by up to +24 % and has
no H2D profile; the Prusa and Orca routes remain available for compatibility
and for the H2D-sized quote bed, but their times are not Bambu-faithful.

The `supports` caveat: with supports on (tree, automatic) overhang-heavy models
take +47..+140 % longer than with supports off. Compare like with like: a
calibration or a reference reading taken without supports must be compared
with a request that sends `supports=false`, and vice versa. The default is
`true`.

## 9. Rate, queue, and timeout budgets

| Budget | Value |
| --- | --- |
| Slice/render rate limit | 3 requests per 60 s sustained, burst 5, per caller (token bucket); repeated rejections add a cooldown up to 30 s |
| Concurrent native slices | 1 (requests are serialised in arrival order) |
| Queue length | 100 |
| Queued + active jobs per caller | 5 |
| Maximum queue wait | 300 s → `503 SLICE_QUEUE_TIMEOUT` |
| Upload lifetime | 600 s → `408 UPLOAD_TOTAL_TIMEOUT` |
| Native slice budget | 600 s → `422 FILE_PROCESSING_TIMEOUT` |
| Python helper budget (conversion, orientation, sizing) | 120 s each → `422 FILE_PROCESSING_TIMEOUT` |
| Render budget | 60 s → `422 FILE_PROCESSING_TIMEOUT` |
| Keep-alive idle timeout | 95 s |

Recommended client timeouts:

- Slice: the theoretical worst case is queue wait (300 s) plus the helper
  budgets (3 × 120 s) plus the native budget (600 s), about 21 minutes. Use at
  least 15 minutes and treat a client-side timeout as "unknown", not "failed":
  the job keeps running and its result is discarded, so do not resubmit in a
  tight loop. Typical quotes complete in seconds to a few minutes.
- Render: 60 s when the queue is idle; the renderer's own budget is 60 s. Add
  the queue wait if you submit renders while slices are queued.
- Pace requests at 20 s intervals or honour `Retry-After` on every 429; the
  reference runners do exactly that.

## 10. `GET /profiles`

Public, unauthenticated, built once at startup and immutable for the life of
the process. It is informational: the slice endpoints remain the authority
and enforce the same limits.

- Schema `r3d-profile-catalogue-v2`, 82 rows: 6 Prusa (P1S and `H2D-QUOTE` at
  0.1/0.2/0.3 mm), 24 Orca (the same two selectors × 3 layer heights × PLA,
  PETG, ABS, TPU), 28 Bambu P1S (7 layer keys × 4 materials), 24 Bambu H2D
  (6 × 4).
- Every row carries `engine`, `printer`, `engine_version`, the ordered
  `slice_selector.parameters` you can post verbatim, `profile_components`,
  the current `effective_profile_sha256`, filament diameter/density, and
  `build_volume_limits_mm` with three separate values:
  `minimum_dimensions_inclusive_mm` (generic 1 mm floor),
  `declared_build_volume_dimensions_mm` (what the profile declares; not an
  admission limit), and `largest_passing_dimensions_inclusive_mm` (the
  largest value per axis that PASSED measurement; an exact match is accepted).
- `machine_resolutions` and `fleet_resolutions` are derived per engine and
  never merged across engines. There are three fleets: bambu (resolved to the
  H2D), orca and prusa (each resolved to their `H2D-QUOTE` profile).
- P1S L-shape note: the Bambu P1S row publishes `256 × 228 × 250`; a part up
  to `238 × 256` is also admitted beside the excluded corner. Use the slice
  endpoint's answer as the final word for parts near either edge.
- Send `If-None-Match` with the strong `ETag`; an unchanged catalogue returns
  `304`. `catalogue_sha256` in the body hashes the canonical content. If the
  catalogue could not be built, the route returns `503
  PROFILE_CATALOGUE_UNAVAILABLE`; slicing is unaffected.

## 11. Material families

| Technology | Materials | Engines | Pricing |
| --- | --- | --- | --- |
| FDM | `PLA`, `PETG`, `ABS`, `TPU` | all three; Prusa uses per-material density in its INI, Orca uses server-owned filament profiles, Bambu uses the vendor Generic filaments | automatic when the slicer reports a positive mass |
| SLA | `Standard`, `ABS-Like`, `Flexible` | Prusa only (`layerHeight` 0.025 / 0.05) | always manual (`null`) |

The density and diameter actually used are echoed in
`profiles.filament_density_g_cm3` and `profiles.filament_diameter_mm` on Orca
and Bambu responses. Material names are matched case-insensitively; the
response echoes the configured spelling.

## 12. What consumers do not get

- No artifact download: the generated `.gcode`, `.sl1`, or Bambu `.gcode.3mf`
  is retained server-side for operators only.
- No pricing mutation: the hourly matrix is operator-managed.
- No readiness detail beyond public `GET /health` (liveness) and `GET /ready`
  (`READY` / `NOT_READY`).
