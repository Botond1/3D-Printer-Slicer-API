# Handoff — 2026-09-02

Written for whoever picks this repository up next. It is deliberately short on
history and long on the things that will bite you. The previous handoff
(`handoff-2026-09-01.md`) still describes production; this one describes the
3.2.0 integration branch that is meant to replace it.

## Where the service stands

Two states coexist:

- **Production** runs the signed main candidate for `bf5e712`
  (`ghcr.io/botond1/3d-printer-slicer-api@sha256:153987840361d60c365da7b105769bb112de807db39a737548b725ea857918ca`)
  behind the LeadPilot-only route. Two engines (Prusa, Orca), 18 catalogue
  rows, 5 s keep-alive, the old 450 HUF rounding. Both consumers are
  integrated in contract and **neither is switched on**, so there is still no
  customer traffic.
- **`feat/bambu-engine-overhaul`** (version 3.2.0) is the three-engine service
  described in `README.md`, `docs/integration-guide.md`, and the "Current
  contract" section of `CLAUDE.md`. It is validated locally and by a
  production-envelope smoke of the built image. It is **not published, not
  deployed, and not routed**. Getting it to production is: PR into `main`,
  merge, manual I11 `workflow_dispatch` publication, then the operator runbook
  deploy — each a separate owner authorization.

The pre-3.2.0 wave narrative was moved verbatim from `README.md` and the
top-level instruction files into `docs/codex/history-waves.md`. Do not move it
back; add dated handoffs instead.

## What changed most recently, and why it matters

**Bambu Studio is now the quoting authority for Bambu Lab printers.** The
calibration question from 2026-09-01 ("which estimator is right?") is answered
by removing the estimator disagreement: `POST /bambu/slice` runs Bambu Studio
`02.08.02.61` headless with the official vendor profiles, and on the ten
reference models the CLI matches the owner's GUI readings within
**-1.1..+0.1 % on time and 0..0.2 % on mass** (supports off). OrcaSlicer 2.3.1
with its bundled BBL profiles is up to **+24 %** off and has no H2D profile at
all. The Prusa and Orca routes stay for compatibility and for the H2D-sized
`H2D-QUOTE` bed, but they are generic-Marlin estimates, not Bambu-faithful.

**Supports change everything.** With supports on (tree, automatic) the
overhang-heavy reference models take **+47..+140 %** longer. `supports`
defaults to `true` on every engine. A reading taken without supports must be
compared with a `supports=false` request, never with the default.

**The Bambu P1S bed is L-shaped.** Bambu Studio refuses to print into an
`18 x 28 mm` corner at the origin (`bed_exclude_area`). With `--arrange 1` the
CLI yawed models that did not fit, which broke the rotation-only transform
contract, so the API now sends `--arrange 0 --orient 0` and places the model
itself. Measured inclusive ceilings: P1S `256 x 228 x 250` placed above the
corner or `238 x 256` beside it; H2D `325 x 320 x 325` (single-filament,
first extruder). `+0.1 mm` on any axis is a 422. The catalogue publishes the
wide triple; a `238 x 256` part is still admitted through real placement.

**Prices moved by 10 HUF.** `1980 s x 800 HUF/h` is exactly 440; the old
hours-first float formula produced `440.00000000000006` and billed 450. The
formula is now integer arithmetic. Expect every quote that sat exactly on a
10 HUF boundary to drop by 10.

**Orca times did not change** although `total estimated time` is now ranked
first: the shipped generic Orca profile only emits
`estimated printing time (normal mode)`. If a future profile emits the total
header, Orca numbers will include the start sequence and go up.

## Traps that have already cost time

**The `.gcode.3mf` extension.** Every `/bambu/slice` returned 500 after a
successful native slice until managed artifact names admitted the double
extension. Anything that validates artifact names (listing, download, ZIP
export, retention) must keep `.gcode.3mf` in its allowlist.

**`xvfb-run` hangs in the container envelope.** Bambu Studio needs a display
only for `--export-3mf` (thumbnail rendering). The root-owned wrapper
`/usr/local/bin/bambu-studio` starts its own Xvfb on a PID-derived display,
writes only under `/tmp`, reaps it on EXIT/TERM/INT, and propagates the exit
status. `tests/unit/js/bambu-image-infrastructure.test.js` pins every line of
it and of the Dockerfile block; edit the test and the source together.

**Bambu `--allow-rotations` takes no value.** Passing `--allow-rotations=0` is
not how it works and must never appear in the Bambu argv; the flag is simply
absent and arrangement is off anyway.

**`BAMBU_PROFILES_ROOT` must be absolute.** Startup refuses to listen
(`STARTUP_BAMBU_REGISTRY_INVALID`, `STARTUP_BAMBU_PROFILE_CHAIN_FAILED`) when
the registry names do not resolve in the vendor resources. A Bambu Studio
upgrade can rename vendor presets; re-check `configs/bambu/printers.json` and
re-measure the envelopes after any AppImage bump.

**The vendored Orca `Custom` parents are byte-pinned** (still true):
`scripts/verify-orca-profile-vendor.js` breaks the image build if
`fdm_machine_common`, `fdm_process_common`, or `fdm_process_marlin_common`
drift. Override in the repository leaf profiles.

**The mirror test is byte-exact.** `tests/unit/js/instruction-mirrors.test.js`
requires `.github/agents` == `.claude/agents` and `.github/skills` ==
`.claude/skills`. Edit the `.github` copy and `cp` it over; never hand-edit
both.

**Traefik closes idle backend connections after 90 s.** The keep-alive
default is 95 s (bounded 1000..120000) for that reason; lowering it below 90 s
reintroduces sporadic `ECONNRESET` on the proxy side.

**Validation runs before the queue now.** A `400` never occupies a queue slot,
and the limiter/queue fairness key on the authenticated principal
(`principal:<slot>`), not the IP, whenever a slice key matched. Tests that
expect per-IP behaviour on authenticated requests are wrong.

**Everything from the 2026-09-01 handoff still applies**: operator pack must be
a git checkout, host Node for the router helpers, `-p slicer-api`, conntrack
rules instead of `--dport 443`, IPv6 arrives as host `INPUT`, MSYS needs
`MSYS_NO_PATHCONV=1` for `origin/main:file` refs.

## Hard rules

- **Never push `claude/sz-b2-orca-headless`.** It contains real customer
  names, lead IDs, and order numbers. The repository is public.
- **Never commit a real IP address, hostname, or credential.** RFC 5737 ranges
  and `.invalid` hostnames only. The safety guard
  (`npm run check:repository-safety`) scans every tracked file.
- **Never read or publish `docs/research/`** (gitignored operator notes) or the
  owner's private Bambu reference models/readings. The calibration runner
  reports only model index and SHA-256 prefix.
- **Route activation, DNS, allowlist, publication, and deployment need direct
  owner approval**, and stopping the running Traefik needs its own.
- **DNS for the API name stays grey-cloud (DNS only).**
- **Do not edit `app/` from a documentation task.** `app/docs/swagger-docs.js`
  still says `version: '3.1.4'` in its OpenAPI `info` block; bumping it is a
  one-line js-developer change that should land with the PR (see "What is open").

## What is open

**OpenAPI `info.version`.** `package.json` and `package-lock.json` are `3.2.0`;
`app/docs/swagger-docs.js` line 21 still reports `3.1.4`. No test pins it, but
`/openapi.json` will lie about its version until it is changed.

**Physical print.** No wall-clock print has been made for any engine. The
Bambu CLI/GUI agreement proves the CLI reproduces the GUI, not that the GUI is
right; the GUI is the owner's accepted reference.

**H2D on hardware.** `325 x 320 x 325` is the CLI's admission ceiling with the
vendor profile, not printed evidence. The single-filament first-extruder area
is a modelling choice: a multi-material job would need the intersection of both
extruder areas.

**SLA.** Still PrusaSlicer `.sl1`, still quote-only (`null` mass and price).
The Elegoo Saturn 4 Ultra needs `.goo`/`.ctb` output and owner Chitubox/Elegoo
Satellite profiles; its envelope is not guessed.

**Infill pattern alignment** across engines remains impossible (PrusaSlicer
rejects `crosshatch`).

**Consumers.** Neither the WooCommerce plugin nor LeadPilot has been switched
to `/bambu/slice` or `/render`. The integration guide is the contract they
should be updated against; the old `/prusa/slice` path keeps working.

## How to verify anything

Never trust a local test run alone for behaviour that depends on the slicer
binaries. Build the image and exercise it in a container with the production
isolation envelope, then compare against the recorded baselines:

1. `git archive` the commit, ship it, `docker build` on the VPS.
2. Run with `--read-only --user 999:999 --cap-drop ALL --init`, tmpfs `/tmp`
   at `uid=999,gid=999,mode=0700`, 4 GiB / 2 CPU / 512 pids, no published ports.
3. Drive it over HTTP from a disposable peer on the `slicer-api-private`
   network; pace at 20 s and honour `Retry-After`.

Regression baselines, all measured on the current build (40 mm PLA cube,
0.2 mm, 20 % infill, supports on):

| Check | Expected |
| --- | --- |
| Bambu P1S cube | 2453 s / 24.0 g / 550 HUF, `placement_mm` present |
| Bambu H2D cube | 2452 s / 23.94 g / 550 HUF |
| Prusa cube | 1980 s / 24.7 g / **440** HUF (was 450) |
| Orca cube | 2760 s / 24.2 g / 620 HUF (unchanged) |
| Bambu P1S envelope | `256 x 228 x 250` and `238 x 256` pass; `256 x 256` and any `+0.1` fail with 422 |
| Bambu H2D envelope | `325 x 320 x 325` passes; `+0.1` fails |
| Orca X/Y envelope | 253.9 passes, 254.0 returns 422 |
| Z envelope, Prusa/Orca | 249.9 passes, 250.0 returns 422 |
| H2D-QUOTE | Prusa 350x320, Orca 347.9x317.9, Z 324.9 |

Local gates before any commit: `npm run test:js`, `npm run test:python`,
