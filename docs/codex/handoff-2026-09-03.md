## What changed, and why it matters

**SLA quotes are real quotes now.** `POST /prusa/slice` with `layerHeight`
`0.025` or `0.05` quotes the Elegoo Saturn 4 Ultra instead of returning a
null-mass, null-price estimate. The engine is still PrusaSlicer 2.8.1 — no new
slicer was added — but the profiles describe the Saturn bed
(`218.88 x 122.88 x 220 mm`, 768 x 432 quote raster) and the numbers come from
the physics of the machine rather than from an FDM-shaped estimator:

- **Time** is `sla-layer-time-v1` from `configs/sla/printers.json`: every layer
  takes the same time, so the estimate is the layer count times a per-layer
  cost (5 bottom layers at 30 s exposure + 6 s motion, 8 transition layers, the
  rest at exposure + 2.5 s motion; exposure 2.5 s at 0.05 mm, 2.0 s at
  0.025 mm). `print_time_source` is `sla_layer_time_model`.
- **Mass** is `usedMaterial_ml x resin density` (Standard and ABS-Like 1.10,
  Flexible 1.05 g/cm3), so SLA prices like FDM.
- `stats.layer_count`, `stats.model_volume_ml` and `stats.support_volume_ml`
  are published; `GET /profiles` grew from 82 to **88 rows** with six
  `SATURN4U` rows.

**The `.sl1` reader used the wrong limit.** One PNG per layer against the
500-entry upload ZIP cap meant any model taller than 25 mm at 0.05 mm answered
`413` in production. The reader now counts layers with its own bound
(`MAX_SL1_ENTRIES`) and reads only `config.ini`.

**Zero support elevation is the quoting convention.** The default 5 mm
elevation makes a large flat plate's support tree exhaust the container's
4 GiB. At zero elevation the object prints directly on the plate — and,
measured, **no pad is emitted at all**: the first SL1 layer of a 20 x 20 mm
footprint covers 414 mm2, the layer count equals height / layer height, and a
support-free model's `usedMaterial` equals its mesh volume exactly. The quoted
resin therefore covers object + supports, never a pad.

**The model volume needed a second source.** `scale_model.py` prints the mesh
volume, but it only runs when a scale or rotation is actually requested, and a
plain quote asks for neither — so `model_volume_ml` was `null` on every real
request. `prusa-slicer --info` reports `volume` (and `manifold`), and the
pipeline already calls it, so that measurement now fills the gap for manifold
meshes.

**`supports=false` was ignored on SLA.** The SLA invocation has no support
flags, and the runtime profile derivation wrote the override only for FDM, so
the request produced the same `supports_enable = 1` profile and the same
`effective_profile_sha256` as the default. The SLA runtime profile now carries
`supports_enable = 0`, which is a different effective profile, exactly as the
contract already said for every engine.

## Traps specific to this wave

**PrusaSlicer's SLA export does not refuse out-of-bed objects.** A 218.98 mm
wide or 220.1 mm tall object exports happily. The API's own INI-derived bounds
are therefore the SLA admission authority, and the catalogue's inclusive
ceiling mirrors the declared metadata until a native envelope sweep measures
the real one.

**SLA support placement is non-deterministic.** Two identical requests for the
same overhang model returned 36.03 ml and 36.25 ml of resin (~0.6 %), so the
same model can quote a slightly different mass and price twice in a row. FDM
does not behave this way. Do not treat a small SLA difference as a regression.

**The `.sl1` is a quote-only raster.** The Saturn prints `.goo`; converting the
`.sl1` needs UVtools, which is not bundled and is not part of the quote path.

**`prusa-slicer --info` volume is only trustworthy when `manifold = yes`.** The
parser refuses everything else rather than publishing a signed-volume artifact
as a measurement.

## What is open

**The per-layer motion time is an assumption.** 2.5 s per layer (6 s for bottom
layers) is a plausible tilt-and-settle cost, not a measured one. Until the owner
compares one real Saturn estimate (Chitubox or the printer's own display)
against `sla-layer-time-v1`, SLA times and prices are internally consistent but
uncalibrated. The registry is owner-tunable exactly for this.

**The Saturn envelope is provisional.** `218.88 x 122.88 x 220` is the declared
metadata used as the admission ceiling, not a measured native edge like the
FDM envelopes.

**Printable output.** SLA remains quote-only. A real print still needs an
external UVtools conversion of the `.sl1`.

Everything open in `handoff-2026-09-02.md` that is not listed here still
stands: no physical print on any engine, H2D `325 x 320 x 325` is a CLI
ceiling rather than printed evidence, the infill pattern cannot be aligned
across engines, and neither consumer has been switched to `/bambu/slice` or
`/render`.
